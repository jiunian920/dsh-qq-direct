# v0.1.7 更新说明 · QQ 自动查看与自主选择

## 自动查看

QQ 直连的主动查看通过本地账本进行。是否接话由当前绑定的智能体判断。确认发言、群聊点名后的直接唤醒、相关跟进或授权私聊接上时，桥重新等五分钟静默。静默满后开始随机窗口，第 20 分钟起每分钟抽一次。

| 窗口分钟数 | 当次扫描概率 |
|---|---:|
| 20 | 0.5% |
| 80 | 1.5% |
| 90 | 约 26.1% |
| 100 | 100% |

第 20 至 80 分钟缓慢线性上涨，80 分钟后按二次曲线加速。扫完启动下一轮。没有新群消息时，本地完成检查。发现新消息时，每次选一个白名单群，向智能体提供至多六条原句、发言人、消息 ID 和北京时间。智能体可以回复或安静结束。自动查看取消每日次数限额。正在处理 QQ 输入、桥暂停或 DSH 暂不可用时，检查会等待。

## 自主选择

在本机 `qq-bridge/config.json` 的 `directSession` 内合并以下字段。

```json
{
  "automaticObservation": {
    "autonomousChoice": true
  }
}
```

公开示例默认关闭此项。启用后，连续空扫两次或累计完成五次扫描都会安排一次自主选择，哪一条先触发就同时清零两套计数。两条条件同次满足时合并成一次回合。真实 QQ 对话会清空连续空扫计数，累计扫描数保留到自主选择排入队列时。如果第五次有新消息，先开正常群查看回合，再安排自主选择。计数和排队状态保存在本地账本中，可以跨重启继续。两种自主触发都没有每日上限；实际模型调用次数与日常组群活跃度、接话和停留情况有关。

自主回合可以休息、通过安全网页工具浏览公开内容、画一幅本机 SVG，或在白名单群和授权操作者私聊发送文字、收藏表情。公开版沿用自主回合的工具范围。群消息正文随正常 QQ 场景交给模型，独立的自主选择入口只带渠道和可用表情提示。

## 从 v0.1.6 升级

1. 在空闲时段退出 DSH，停下 QQ 桥，备份本机 `config.json` 和 `state/`。
2. 更新桥和 DSH 插件源码。在 `qq-bridge` 下用 Node.js 22.13 或更高版本运行 `npm ci` 和 `npm test`。
3. 保留本机配置和数据。旧 `maxPer24Hours`、`cooldownMinutes`、`freePer24Hours`、`topics` 字段已退出这套调度。愿意开启自动安排自主选择时，请显式设置 `autonomousChoice: true`，有旧的 `freePer24Hours` 值也一样。
4. 重新打开 DSH 和 QQ 桥，确认两侧仍指向原主会话。程序会在原 SQLite 卷上初始化新版计数，保留旧用量与历史扫描日志。

`npm test` 中的自动查看回放使用假时钟和假 QQ 消息，覆盖概率边界、静默重算、计数清零、第五次有消息的顺序、两个条件合并、默认关闭及渠道权限。安装包只包含源码、空配置示例和离线测试。
