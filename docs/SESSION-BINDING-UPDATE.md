# QQ 直连会话绑定更新说明

## 修复了什么

原先 QQ 桥和 DSH 插件各自从配置读取同一个主会话 ID。新开桌面对话后，如果配置仍指向旧会话，QQ 消息会继续送到旧会话。早期补丁通过文本指针跟随用户输入，但写入失败时可能出现两端目标不一致，而且定时任务等事件也可能带有 `user` 来源标签。

新版让插件把自动跟随结果写进桥和插件共用的 SQLite 账本。两端从同一条绑定记录确定目标会话。重启后可以恢复已保存的绑定。写入失败时保持原目标，并允许下一条符合条件的输入重试。

## 默认行为与启用方法

现有部署可继续固定绑定。首次安装时，在 QQ 桥的 `directSession.sessionId` 和 DSH 的 `qq-direct.config.sessionId` 填写同一个会话 ID，并让插件指向桥的同一份 SQLite 账本。

需要自动跟随时，在 DSH 插件配置里启用 [配置示例](dsh-profile.example.yml) 中的 `followDesktop`，填写目标工作区的绝对路径和预设名。合格的新建顶层会话收到第一条符合条件的桌面输入后才会接手。切换窗口、打开旧对话、QQ 注入、缺少桌面请求字段的定时输入和派生会话都不会改绑。已有 QQ 回合继续使用原来的会话及权限，结束后再切换。等待两边心跳对齐期间，尚未投递的消息留在账本。

来源检查使用当前 DSH 桌面输入携带的请求 ID、客户端时区和调用者字段。拥有受信任本地 RPC 权限的程序仍可能构造相同的请求形态。自动跟随适合受信任的桌面部署，可按需启用。有关启动后第一次切换、手动改绑和关闭自动跟随的细节，见[架构手册](ARCHITECTURE.md#auto-follow)。

## 从文本指针试验版升级

1. 先确认正在使用的主会话 ID。备份本机插件、桥代码、两端配置和 SQLite 账本。
2. 等当前 QQ 回合结束。把两端配置的初始 `sessionId` 对齐到刚确认的会话，再一并升级桥和 DSH 插件。新版使用 SQLite 绑定，原文本指针不会自动迁入。
3. 按需配置 `followDesktop`，用当前 DSH 的方式重载插件并重新启动桥。先检查桥和插件的运行心跳是否指向同一会话，再做验收。
4. 在指定工作区用相同预设新开一场对话，在桌面发第一条消息。核对两端心跳切到新会话，然后从获授权的 QQ 私聊发一条带独特短语的测试消息，确认它进入新会话，且回复回到原渠道。最后回到旧会话发一条桌面消息，核对绑定仍在新会话。
5. 若切换时有回复已经交给 QQ 网关，先核对真实发送回执再决定是否重发。新版会拦住尚未交给网关的旧会话发送任务，包括仍在合成的语音。

## 验证记录

`qq-bridge` 的 `npm test` 已通过。新增会话绑定回归使用临时 SQLite、模拟 DSH 事件和模拟 QQ 网关，验证了来源与范围筛选、旧回合权限、写入失败重试、心跳不同步时的等待、跨切换语音拦截、重启恢复和新会话发送。真实桌面和 QQ 的双向验收可按上述步骤进行。
